# Технічна специфікація: Математичний тренажер (Android)

## 1. Огляд

Android-додаток для дітей майбутнього 3-го класу — тренажер з арифметики (додавання, віднімання, множення, ділення). Мета: швидкий вхід у тренування без зайвих екранів, збереження налаштувань між сесіями, вікторина з розбором помилок, цікаві факти як заохочення, базова статистика прогресу для дитини й батьків.

Платформа: Android, minSdk 24, targetSdk — актуальний.
Публікація в Google Play не планується.

---

## 2. Технічний стек

- **Мова:** Kotlin
- **UI:** Jetpack Compose, Material 3
- **Адаптивність:** `androidx.compose.material3.windowsizeclass` (WindowSizeClass: compact/medium/expanded) + Material 3 Adaptive для layout-рішень телефон/планшет
- **Архітектура:** MVVM, Unidirectional Data Flow, Repository pattern
- **Навігація:** Navigation Compose, типобезпечні маршрути через `kotlinx.serialization`
- **DI:** Koin (`koin-androidx-compose`)
- **Асинхронність:** Kotlin Coroutines + Flow
- **Персистентність:**
  - Room — статистика, історія помилок
  - DataStore (Preferences) — налаштування користувача (останній режим/рівень/дії/мова/тема)
- **Локалізація:** укр / рос / англ, через `AppCompatDelegate.setApplicationLocales()`, зміна на льоту без ручного перезапуску
- **Факти:** зберігаються як `string-array` в `values/`, `values-uk/`, `values-ru/` (не окремі JSON-файли)
- **Тестування:** JUnit5 + Turbine, модульні тести генератора прикладів. UI-тести — не в MVP.
- **Навігаційна структура:** Single Activity (`MainActivity`) + `NavHost` з composable-екранами

---

## 3. Архітектура застосунку

Single Activity підхід. Всі екрани — composable функції в `NavHost`.

Шари:
- `ui/` — composable екрани, ViewModel-и
- `domain/` — генератор прикладів, логіка рівнів складності, бізнес-правила
- `data/` — Room (Entities, DAO), DataStore, репозиторії
- `di/` — Koin модулі

---

## 4. Локалізація

- Мови: українська, російська, англійська
- Дефолт: мова пристрою, якщо вона входить у список (uk/ru/en) — інакше en
- Зміна мови вручну — в налаштуваннях, застосовується миттєво (`AppCompatDelegate.setApplicationLocales`)
- Ресурси: `values/strings.xml` (fallback = en), `values-uk/strings.xml`, `values-ru/strings.xml`
- Банк фактів локалізується так само, через ресурсні масиви (див. п.8)

## 5. Математична логіка

### 5.1 Дії
Додавання, віднімання, множення, ділення. Користувач обирає одну, декілька або всі — незалежні toggle-перемикачі, зберігаються як налаштування.

### 5.2 Рівні складності: легкий / середній / складний / зірочка

**Додавання / віднімання**

| Рівень | Діапазон і типи |
|---|---|
| Легкий | В межах 20 без переходу через розряд (12+5, 18-6); двоцифрове + одноцифрове без переходу через розряд і без переходу в нову сотню (52+7, 81+3, 65-4) |
| Середній | В межах 100 без переходу через розряд (45+32, 78-56); прості багатоступеневі (3+2-4); з невідомим доданком (5+□=12) |
| Складний | В межах 100 з переходом через розряд (47+38, 62-27); багатоступеневі середньої складності з невідомим доданком (53+□=81) або типу (23+42-18) |
| Зірочка | В межах 1000 (456+238, 823-467); складні багатоступеневі з переходом через 100 (23+□+46=93); невідомий зменшуваний/від'ємник (□-15=27, 82-□=45); з дужками ((34+16)-27) |

**Множення / ділення**

| Рівень | Діапазон і типи |
|---|---|
| Легкий | Таблиця 2-5 |
| Середній | Повна таблиця 2-10 |
| Складний | Двоцифрове × одноцифрове (24×3) |
| Зірочка | Двоцифрове × одноцифрове з переходом через розряд (27×4); ділення двоцифрового на одноцифрове (78:6); множення/ділення на 10 і 100 (23×10, 400:100); приклади на порядок дій (6×3+15, 50-4×8); зворотні приклади (□×8=64, 96:□=12) |

Примітка: ділення з остачею НЕ використовується — ще не вивчається в програмі.

### 5.3 Типи завдань
- Стандартні приклади ("розв'яжи")
- З пропущеним компонентом (□+4=9, 6×□=18) — присутні на всіх рівнях середньої+ складності відповідно до таблиці вище

### 5.4 Генератор прикладів
- Рандомна генерація в межах діапазону відповідного рівня і дії
- Без повторів одного й того самого прикладу підряд в межах однієї сесії
- Модульні тести (JUnit5) обов'язкові для перевірки коректності діапазонів по кожній комбінації рівень×дія

## 6. Режими роботи

### 6.1 Вільна практика
Приклади генеруються нескінченно (або до зупинки користувачем) відповідно до обраних дій/рівня. Цікаві факти показуються кожні 5 прикладів.

### 6.2 Вікторина
- Довжина сесії: 10-15 прикладів (фіксована кількість, обирається в налаштуваннях або дефолтна)
- Два підрежими:
  - Прогресія складності (легкий → середній → складний → зірочка)
  - Перемішування прикладів різної складності
- Без таймера — жодних обмежень часу
- Цікаві факти — кожні 5 прикладів (так само, як у вільній практиці)
- Після завершення — екран розбору результатів: список **усіх** прикладів вікторини (не лише помилкових), кожен з індикацією правильно/неправильно; для неправильних — правильна відповідь поруч
- Дружній фідбек на кожну відповідь: без негативних звуків/анімацій на помилку, заохочувальний тон навіть при неправильній відповіді

## 7. Налаштування та UX-потік

- **Перший запуск:** коротке налаштування — вибір дій, рівня складності, режиму (вільна практика / вікторина)
- **Головний екран (усі наступні запуски):** компактний блок поточних налаштувань (наприклад "Множення · Середній · Вікторина") + велика кнопка "Старт" + іконка налаштувань для зміни в один клік
- Налаштування зберігаються в DataStore, застосовуються автоматично при наступному запуску
- Мінімум проміжних екранів між відкриттям застосунку і початком розв'язування прикладів

---

## 8. Банк цікавих фактів

- Показ: кожні 5 прикладів, незалежно від режиму (вільна практика чи вікторина)
- Категорії: тварини, космос, динозаври, рекорди природи, математика
- Формат: 1-2 речення, яскраво і коротко
- Зберігання: `string-array` ресурси, окремий масив на категорію (`facts_animals`, `facts_space`, `facts_dinosaurs`, `facts_nature_records`, `facts_math`) в `values/`, `values-uk/`, `values-ru/`
- Логіка показу: ротація без повторів у межах сесії/до вичерпання банку, потім скидання
- Наповнення банку (~150 фактів на кожну з трьох мов) — окрема задача на етапі розробки, не потребує додаткового узгодження змісту заздалегідь

---

## 9. Статистика та прогрес

- Один екран "Мій прогрес", доступний і дитині, і батькам
- Плашки по кожній дії (додавання/віднімання/множення/ділення) з відсотком правильних відповідей
- Позначення слабких місць (наприклад "множення на 7-9 — варто повторити")
- Дані — з Room, оновлюються після кожної вікторини/сесії практики
- Без окремих акаунтів, без складної аналітики

## 12. Рекомендований порядок реалізації

1. Модель даних (Room entities, DataStore keys) + генератор прикладів з модульними тестами
2. Базова навігація (NavHost) і головний екран з дефолтними налаштуваннями
3. Екран налаштувань (дії, рівень, режим, мова)
4. Екран вільної практики
5. Екран вікторини + розбір помилок
6. Банк фактів і логіка показу
7. Екран статистики/прогресу
8. Локалізація (uk/ru/en) — рядки інтерфейсу + факти
9. Адаптивний layout (WindowSizeClass для телефон/планшет)
10. Доступність (шрифт/контраст) — за наявності часу
